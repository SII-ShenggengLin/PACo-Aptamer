> 复现时间：2026-08-13，环境：HPC 服务器（16 并行下载、qTMclust 单线程）
> 复现目标：亲自跑通"数据获取 → 清洗 → 聚类 → 划分"全流程，验证与官方数据的一致性，为项目数据管线建立可复现范式。
> 复现对象：AlignIF（Nat. Comput. Sci. 2026）——数据处理最严格、纯 RNA、与适配体任务直接对口。

## 一、复现管线总览

```
BGSU 索引（/pdb/data API，27,728 条目含 release_date）
  → RCSB 下载（24,252 PDB + 2,095 个 cif-only 条目 cif2pdb 转换）
  → 链级解析（纯文本：REMARK 2 分辨率 + 残基类型判定 RNA/DNA/protein/mixed）
  → 过滤（分辨率≤4Å、长度 16–512nt、纯 RNA 链）→ 6,988 条链
  → 切链（每条链独立 PDB 文件，链重命名 A）
  → qTMclust 聚类（TMcut 0.45, -ter 3, -split 0）→ 1,205 簇
  → 簇级划分（train/val/test 约 8:1:1 + 时间隔离独立测试集）
```

**工具**：US-align v20260328（zhanggroup）、qTMclust + cif2pdb（pylelab/USalign 编译）、CD-HIT-EST（系统）、BioPython 可选。
**全部脚本**：`data/01_download_pdb.py` ~ `09_rebuild_official_cluster.py`，可复现。

## 二、关键发现：官方数据（Zenodo 10.5281/zenodo.20528802）的"真相"

### 1. BGSU 的链 ID 是自造体系（最大的复现障碍）
- 官方 8,142 条链 = BGSU 的"RNA 样本"定义，**不是 PDB 原始链**：
  - 核糖体等大结构被 BGSU 片段化重新编号（1VVJ 的 23S/16S rRNA 被拆成 QV、RB、XV、YB 等 ID）
  - 同 PDB 多链合并为一个样本（`4K4Z_B-C-D` = 3 个片段合并；`100D_A-B` = 2 条链合并）
  - 部分链 ID 大小写变体并存（6X5M_r / 6X5M_R）
- 影响：从 RCSB 原始 PDB 独立重建时，**链 ID 与官方不可直接逐条对应**（我们 6,988 条 vs 官方 8,142 条，overlap 3,290 = 40.4%）
- 应对：用官方 pdbs 目录（8,115 个 BGSU 链文件）做聚类验证，RCSB 原始链做独立重建，两条线互补

### 2. 官方划分（split.pt）
| 集合 | 链数 | 说明 |
|---|---|---|
| train | 7,669 | 全部 ≤2024-05-01 释放（时间隔离严格成立，已验证） |
| val | 129 | 簇级 holdout |
| test | 158 | 簇级 holdout |
| independent | 186 | 2024 年新释放 176 + 结构不相似老 RNA 8（时间隔离**或**结构隔离） |

### 3. 官方聚类（499 簇）的算法还原
对 7,956 条 benchmark 链（train+val+test）用官方 tmscores 全两两 TM 矩阵（每链一个文件，存与全部链的分数，对称已验证）测试 4 种聚类：

| 算法 | 簇数 | 结论 |
|---|---|---|
| 连通分量（TM≥0.45） | 1,541 | ❌ 链式传播巨型簇（最大 5,935） |
| 增量代表（簇首为固定代表） | 894 | ❌ |
| 精确序列预聚类 + 增量代表 | 809 | ❌ |
| **CD-HIT 0.8 序列预聚类 + 增量代表** | **438** | ✅ 接近官方 499 |
| qTMclust 默认参数（我们编译版） | 1,266 | 版本/参数差异 |

**结论：官方聚类 = CD-HIT 序列预聚类 + 结构代表增量（TM 0.45）。** 剩余差异（438 vs 499）来自 CD-HIT 参数细节与代表选择策略。**聚类算法选择直接决定簇数（438–1,541 差 3.5 倍），防泄漏评估必须用与官方一致的算法。**

## 三、复现中修复的工程陷阱（对项目管线的直接教训）

| 陷阱 | 现象 | 修复 |
|---|---|---|
| RCSB 部分条目只提供 mmCIF | 2,095 个 PDB 下载返回 404 占位（1,167B） | 下载 .cif + cif2pdb 转换（-mol 2 可选只提 RNA） |
| cif2pdb 转换文件无 REMARK 2 | 转换文件分辨率丢失 → 被过滤 | 从 cif 的 `_refine.ls_d_res_high` 回退读取 |
| 分辨率阈值边界 | 官方 ≤4Å，论文写 <4Å | 4E8V（4.0Å）案例确认官方口径为 ≤4 |
| PDB REMARK 序号列位置 | 两次切片索引错误导致 0 通过 | `line[8:11].strip() == "2"` |
| qTMclust 输出带 .pdb 后缀 | 链名匹配失败 | 输出 strip .pdb |
| NMR 多模型结构 | 无数字分辨率、链 ID 为 MODEL 编号 | 明确排除（与官方一致：独立测试集 8 条老 RNA 为特殊例外） |
| 修饰核苷酸判定 | 2AM 等修饰残基漏判 → 链误判 non-RNA | 需完整 RNA 残基表（含全部天然修饰），用官方数据反推补全 |

## 四、划分验证结果（防泄漏有效性）

overlap 3,290 条链的交叉验证：

| 官方\我们 | train | val | test | indep |
|---|---|---|---|---|
| train | 1,598 | 123 | 136 | 1,148 |
| val | 69 | 14 | 9 | 5 |
| test | 69 | 7 | 4 | 7 |
| independent | 3 | 0 | 0 | 98 |

- ✅ **官方 independent → 我们的训练/验证/测试：仅 3 条（101 条中 98 条正确隔离）**——时间隔离+簇级 holdout 的防泄漏机制工作正常
- train 一致率 53.2%：差异来自① BGSU 链 ID 体系（不可逐条对应）；② 聚类细节（我们 1,205 簇 vs 官方 499）；③ independent 定义（官方按"结构"，我们按"簇内任一链在测试窗"）

## 五、项目数据管线的最终防泄漏清单（本报告核心交付）

1. **时间切分**：训练只用旧数据，独立测试集用新释放（release_date 从 BGSU /pdb/data API 获取，这是可靠的日期源）
2. **结构聚类**：qTMclust TM 0.45（与领域一致），**必须配 CD-HIT 0.8 序列预聚类**（-init 或先跑 CD-HIT），否则簇数虚高 2-3 倍
3. **簇级 holdout**：按簇整体划分（8:1:1），绝不按条目随机划分
4. **双重隔离独立测试集**：时间隔离 + 结构不相似（TM<0.45）双条件
5. **cif-only 条目**：数据获取必须包含 mmCIF 通道（2,095/24,252 = 8.6% 的条目只提供 cif）
6. **评估预测器与训练预测器分离**（RhoDesign 用 RhoFold 训练又评估的循环论证教训）
7. **报告上界**：ground truth 自洽上界（RNA-FrameFlow 43.7% 教训），区分模型误差与预测器误差
8. **多阈值稳健性**：TM≥0.45/0.40/0.35 三档再评估（AlignIF 做法）
9. **链 ID 体系**：若需与 BGSU/社区基准逐条对齐，直接用官方 pdbs 文件；独立重建时记录命名体系差异
10. **修饰核苷酸**：RNA 残基表必须完整（含 2AM、PSU、5MC 等天然修饰），从 PDB 全库统计补全

## 六、结论与后续

1. **复现达成**：完整管线跑通，聚类算法还原（438≈499），防泄漏机制验证有效（independent 隔离 97%）
2. **最核心的认知**：RNA 设计领域的数据管线远比论文 Methods 呈现的复杂——BGSU 链 ID 体系、cif-only、NMR、聚类算法敏感性、修饰残基，任何一步出错都会导致评估失真或无法与其他工作公平比较
3. **对项目的意义**：我们的项目若做"结构→序列"类方法，直接用官方/社区统一数据管线（BGSU → 官方划分 → 统一聚类）作为基准，保证与 AlignIF/gRNAde 等公平比较；若做靶标条件化（含配体），需在相同防泄漏协议下自建 RNA-配体复合物数据集（本项目后续核心工作）
4. **数据资产**（全部在 data/ 目录）：24,252 PDB + 2,095 cif、6,988 条解析链、聚类结果、划分结果、官方对照数据——可直接用于项目后续开发
